# search-candidate-validator

**C24 — exact source-backed candidate validation.**

**Status:** substantive source exists for nomination validation against plan identity, live security,
projection membership, exact retained revisions, representations, unit anchors, digests, assurance and
disclosure ceilings. It is not yet proven through the complete supported real-Qdrant daemon path.

## Owns

- request/plan/leg correspondence checks;
- final live access, purge and emission-fence revalidation;
- collection/profile/epoch/membership checks;
- saved/unsaved overlay shadow rejection;
- exact revision and representation readback through vendor-neutral ports;
- byte length, content digest, unit and anchor validation;
- coordinate-map, residency, assurance and disclosure checks;
- stale/unreadable/denied candidate removal;
- typed replan and coverage-gap disposition.

## Must not own

- treating Qdrant payload text or cached snippets as evidence;
- client admission, task or finish authority;
- concrete revision-store/redb/Qdrant/process adapters;
- silently keeping candidates from a contaminated scoring/IDF leg;
- source acquisition or projection publication.

## Current gap

The validator is a `SOURCE` kernel. Product completion requires real Qdrant nominations, authoritative
projection-to-source mapping, exact retained-revision adapters, result projection and end-to-end deny,
stale, unreadable and index-loss fixtures. No package README or source test can substitute for that live
qualification.
