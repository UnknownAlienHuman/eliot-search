# Working on query and results

Read the [architecture](../../docs/architecture/README.md) and
[implementation](../../docs/implementation/README.md). Connect one request to useful source-backed
results. Update planning, execution, validation and output together where their current models differ.

Resolve the selected scope and pin one coherent published view before retrieval. Use actual profile,
source/revision and coordinate data; do not manufacture task-plan hashes, grants or fixture IDs to
satisfy old constructors. Keep vendor I/O in the existing adapter, with one request deadline.

Preserve one final rank through validation/projection. Fusion identity describes the same published
evidence; the leg name identifies its score contribution, not a new result. Normal top-k makes no
exhaustiveness claim. Reopen actual retained bytes before emitting source evidence.

Use one bounded query window when continuation is needed. Advance its cursor after successful
delivery, remove expired state and avoid full-corpus scans/hashes per page. Optional expansion uses
that same result state; ordinary source/revision/range references need no handle lifecycle platform.

Current packages are code locations. Combine pure stages and duplicated window/handle owners when
their split adds no real dependency boundary; do not create a new port for every function.
