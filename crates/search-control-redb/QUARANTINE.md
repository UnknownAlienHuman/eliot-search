# Historical administrative quarantine

This file described an optional quarantine marker layered onto the generic control journal. It is not a
baseline product subsystem.

A corrupt, unsupported or unresolved root is refused and excluded by the actual root/control owner. The
application may report the reason and leave the data untouched. It does not need a permanent quarantine
receipt, publisher suspension protocol, owner-handoff ceremony or no-clear marker format.

Keep fail-closed open/schema validation and content-free diagnostics. Remove the quarantine record/API and
its exclusive fixtures with the journal platform. Current control and recovery responsibilities are in
[README.md](README.md), [FUNCTIONS.md](FUNCTIONS.md) and the
[publication owner](../search-index-qdrant/search-publication/README.md).
