# Working on preparation

Read the [architecture](../../docs/architecture/README.md),
[implementation guide](../../docs/implementation/README.md) and [preparation map](README.md).

Preparation turns one retained revision into one derived product and structure-first UnitSet while preserving
truthful evidence coordinates. Decode/parse once and pass the owned result forward. Do not reopen/reparse inside
an adjacent in-process stage merely to manufacture a receipt; validate persisted/external artifacts at their
actual acceptance boundary.

Change materializer, unitizer, prepared-artifact persistence and immediate publication/query consumers
together. Remove duplicate legacy stores, nested manifests, discarded canonical encodings and receipt-bound
formats with their callers. Package separation is optional; do not add a generic pipeline, provider registry or
compatibility family.

Keep transformations/profile/source maps only when a real consumer needs them. Model/tokenizer packing is a
derived projection, not source occurrence identity. Reuse outputs by exact input/context/model/options, not by
whitespace-normalized text or positional IDs.

## Optional enrichment currentness

The established `search-code-enricher` audit found heuristic parsing, receipt/assurance machinery and no external
production consumer at the inspected revision. That is revision-specific evidence, not a permanent current fact.
Before deletion, recheck current manifests, Rust/non-Rust callers, feature wiring, targets, tests and workflows.

Do not repair or expand that framework merely because it remains in the workspace. Add Tree-sitter/SCIP/Ctags/
SARIF only when one concrete source-backed orientation consumer selects a narrow profile. If no current consumer
or selected profile exists, delete the package, exclusive fixtures and dependency edges.

After production changes, run minimal Rust 1.98 compiler/Clippy for changed preparation and immediate consumers.
Focus on one retained read/parse, exact or mapped ranges, bounded memory, restart artifact readback/rebuild and no
stage leak. Historical format/golden/qualification matrices leave with their APIs.
