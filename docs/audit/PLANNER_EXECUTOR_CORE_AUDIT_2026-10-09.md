## Result

The planner and executor contain useful deterministic recipe/DAG, pin, population, cancellation, fusion and coverage concepts. They are not safe product authorities yet: plans, tickets, outputs and execution state are public caller-shaped structures; canonical identity omits behavior-affecting fields; aggregate budgets are not actually enforced; and coverage can be forged by map cardinality.

The accepted sequence is now:

```text
#287 → #288 access compiler
→ #277 capability registry
→ #290 opaque canonical plan + complete budget/absolute-deadline model
→ #278 exact ranking/evidence core
→ #291 private executor + aggregate ledger + exact terminal outcomes
→ #279 live product pipeline
```

PR #125 is closed as packet-only. It is not an implementation branch.

## Findings

### F91 — CRITICAL — Accepted plans and legs are caller-constructible

`CapabilitySet`, `LegBudget`, `PlannedLeg` and `CompiledSearchPlan` expose public fields. `compile_plan` accepts caller capability booleans, an authorized-scope value and caller-provided safe indexed legs.

A caller can build or mutate a matching-looking plan without the canonical capability/access/scope compiler.

**Owner:** #290 after #277/#287/#288.

### F92 — CRITICAL — Plan digest omits load-bearing behavior

The current plan fingerprint covers only a subset of request/snapshot/scope/budget/leg data. It omits, among other fields:

- capability/ranking/profile revision;
- effective grant and budget-class identity;
- several global budget axes;
- omitted-capability/partial policy;
- leg dependency graph;
- candidate/CPU/memory ceilings;
- cancellation/completion policy;
- safe indexed population/route/predicate/proof fields.

Two materially different executable plans can share one digest.

**Owner:** #290.

### F93 — HIGH — Plan identity uses a custom mixer and saturating fallback

`CompiledPlanDigest` is generated by a package-local four-lane FNV-like mixer. `leg_id` conversion uses `unwrap_or(u64::MAX)`, collapsing conversion failure into a legitimate byte sequence.

**Owner:** #290 through #237.

### F94 — HIGH — Deadlines are divided into fresh per-leg durations

`allocate_leg_budgets` divides request `deadline_ms` by leg count. This is not a correct model for either parallel legs or a dependency chain and encourages adapters to start a new timer for each leg.

The request must have one absolute monotonic deadline. A leg may receive a narrower phase ceiling, but cannot reset or extend the parent deadline.

**Owner:** #290/#291.

### F95 — HIGH — Aggregate budgets are not enforced

`ExecutionGuard.max_candidates` is populated from `max_validated_candidates` and never consumed. The executor has no complete request-level ledger for aggregate nominations, validated candidates, source-read bytes, materialized/output bytes, CPU/work, memory or progressive frames.

Per-leg ceilings do not prove the request stayed within the admitted total.

**Owner:** #290/#291.

### F96 — CRITICAL — Tickets, outputs and execution state are public/cloneable

`LegTicket`, `LegOutput`, `RawNomination` and `ExecutionState` can be assembled or cloned by ordinary callers. `ExecuteError::PlanDigestMismatch` exists but is not actually used to verify plan admission.

**Owner:** #291.

### F97 — CRITICAL — Completion can be forged by count equality

`classify_completion` checks that the number of stored output keys equals `plan.legs.len()` and that stored outputs report complete status. It does not prove that those keys are exactly the planned leg IDs or that each output matches the accepted ticket, kind, population and profile.

A map with the same number of foreign IDs can be classified complete.

**Owner:** #291.

### F98 — HIGH — Backends do not receive one remaining operation budget

The request guard has one computed deadline tick, but public leg tickets carry relative `deadline_ms` and an issue time. Generic and indexed backend seams do not receive a non-resettable absolute remaining deadline, cancellation reference and aggregate budget ledger, nor is one mandatory post-call accounting check enforced by the core.

**Owner:** #291.

### F99 — CRITICAL — Indexed candidate identity includes the leg ID

The indexed adapter constructs:

```text
candidate:{leg_id}:{point_id}
```

The same physical point from two retrieval legs receives different candidate IDs and therefore cannot merge during fusion. Leg provenance must be separate from provider-neutral immutable candidate identity.

**Owner:** #278/#291.

### F100 — HIGH — Cancellation erases terminal execution evidence

`cancel` clears stored outputs. Content may need to be released, but coverage then loses which legs already executed, completed or partially completed before cancellation.

**Owner:** #291.

### F101 — HIGH — Scheduler admission is caller-shaped

`SchedulerSnapshot` and `owner_id` are ordinary inputs rather than an owner-issued finite queue slot/lease with exact release semantics.

**Owner:** #291.

### F102 — HIGH — Generic output uniqueness checks only caller candidate IDs

`dispatch_leg` rejects duplicate `candidate_id` strings, but a backend can represent the same underlying point/evidence under multiple different IDs. Full immutable point/source/unit/profile evidence must define uniqueness and conflict handling.

**Owner:** #278/#291.

## Required design boundaries

### Canonical planning

```text
normalized versioned request
+ #287 validated grant/effective ceilings
+ #288 canonical scope/access population
+ #277 accepted capability/profile registry
+ immutable source/route/security observations
+ accepted ranking requirement
+ one absolute deadline
→ opaque CompiledSearchPlan
```

The plan digest binds every executable field, not a convenience subset.

### Request execution

```text
opaque plan
+ owner-issued scheduler slot
+ #274 checkpoint
+ one absolute deadline/cancellation
→ private RequestExecution
→ one-use LegTicket
→ exactly one validated terminal result per planned leg
→ aggregate ledger and truthful coverage
```

No ordinary caller mutates execution maps or marks a leg complete.

### Ranking handoff

Candidate identity is independent of leg ID and contains full immutable evidence. Contributing leg/rank is retained separately and canonically. #278 owns exact ranking arithmetic and evidence equality; #291 owns one validated terminal leg set.

## Useful existing mechanics to preserve

- closed recipe/body validation;
- deterministic typed DAG concept;
- explicit omitted capability vocabulary;
- process-local scheduler lanes and queue intent;
- route/epoch pin acquisition;
- same-population retrieval/IDF/count intent;
- whole-leg contamination rather than hit-level repair;
- explicit complete/partial/failed/unavailable/timed-out/cancelled classes;
- raw backend scores treated only as within-population nominations.

Preserve these while removing public authority and incomplete budgets/identity.
