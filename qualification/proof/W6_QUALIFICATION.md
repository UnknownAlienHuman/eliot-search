# W6 subject resolution, comparison and exact-proof qualification contract

**Status:** `NOT_EXECUTED`  
**Architecture:** ELIOT Search 8.4, S21–S25, H13, H15, P11–P12  
**Scope:** deterministic resolution ladder, bounded material ambiguity, repository-lineage independence,
configuration-aware descriptive comparison, exact predicate qualification, authoritative frozen
denominator and complete-negative proof.

A convincing example, high top-ranked score, parser compilation, regex unit test or empty indexed result
is not qualification. Every mandatory probe in [`probes.toml`](probes.toml) must execute against exact
accepted package/API/profile/fixture identities and receive independent review.

## Owners

| Evidence | Owner |
|---|---|
| request normalization, ladder, ambiguity and resolution receipt | `search-subject-resolver` |
| lineage collapse, evidence-role alignment, cfg variants and descriptive matrix | `search-comparator` |
| predicate profile, denominator, execution accounting and proof report | `search-exact` |
| authoritative inventory/source view | `search-source-registry` / `search-source-reconcile` |
| exact revision/anchor readback | `search-revision-store` |
| current grant/live deny/purge checks | `search-access` |
| structural IR/profile assurance | `search-code-enricher` |
| exact handles and final source-backed validation | `search-handles` / `search-candidate-validator` |
| control corpus/evidence aggregation | `search-eval` |
| final receipt acceptance | integration owner + independent reviewer |

A package may produce but cannot accept its own evidence.

## Frozen inputs

Before execution, publish immutable identities for:

- repository commit, Rust toolchain and `Cargo.lock`;
- accepted contracts/domain/ports/access/source/revision/currentness/overlay/code/query API digests;
- source view, workspace view and immutable reference portfolio revisions;
- resolution-ladder profile and normalization fixture digest;
- repository lineage/copy relation fixture and comparison policy profile;
- exact predicate schema and engine/provider artifacts from [`profiles.toml`](profiles.toml);
- exact structural IR/profile digest for structural predicates;
- authoritative inventory and exact revision/anchor fixture manifests;
- effective configuration, resource envelope and all probe bytes/digests.

Mutable branches, floating dependencies, unspecified regex behavior, unqualified lineage heuristics and
ad-hoc candidate files are invalid inputs.

## Execution order

1. Execute request normalization and coherent source/workspace/security context fixtures.
2. Exercise every resolution-ladder tier and explicit-reference failure semantics.
3. Execute same-name, renamed analogue, overload/entity-kind, cfg and truncated ambiguity fixtures.
4. Revalidate resolution receipts under source-view/owner/access/purge/shadow/currentness/profile drift.
5. Build validated comparable implementations and execute exact/ambiguous lineage relation fixtures.
6. Align definitions/tests/callers/docs/configuration roles and execute cfg overlap/exclusion cases.
7. Produce shared/variant/outlier/locally-absent/conflict/unknown matrix and bounded recommended reading.
8. Audit output for absence of normative correctness/adoption claims and raw vendor scores/types.
9. Qualify exact literal, safe regex, qualified-symbol, structural and record-field predicate profiles.
10. Freeze authoritative denominators from inventory, access/currentness and optional authenticated
    unsaved snapshots without using indexed candidates.
11. Execute complete match/no-match, unreadable, revision unavailable, encoding, drift, timeout,
    cancellation, access/purge and unsaved expiry/restart cases.
12. Execute exact checkpoint timeout-after-commit/readback/resume fixtures.
13. Verify complete-negative report and historical-versus-current revalidation semantics.
14. Publish immutable raw outputs and independent review. Only then may P11/P12 evidence be accepted.

## Mandatory properties

### Subject resolution

- ladder order is explicit handle/cursor → qualified key → exact normalized name → signature/entity kind
  → structural/lexical;
- invalid explicit reference does not silently fall through as absent input;
- same name, top rank or close similarity never proves one subject;
- renamed/aliased occurrences collapse only with accepted equivalence evidence;
- material overload/entity-kind/signature/configuration distinctions remain visible;
- ambiguity is bounded, deterministic and exposes truncation/coverage;
- all candidates bind one coherent source/workspace/security/profile fence;
- a higher-priority incomplete step prevents lower-priority resolved success;
- resolution receipt is invalidated by material view/owner/access/purge/shadow/currentness/profile drift.

### Cross-repository comparison

- local subject must be resolved or explicitly selected from ambiguity;
- comparable basis and uncertainty are source-backed and visible;
- forks/mirrors/proven copies count once for independent evidence;
- ambiguous lineage is neither collapsed nor counted confidently independent;
- definitions, tests, callers, documentation and configuration remain separate evidence roles;
- mutually exclusive cfg variants are variants, not conflicts;
- unknown cfg predicates are not unconditional;
- conflicts require overlapping applicability plus incompatible source-backed observations;
- local absence from incomplete evidence is not complete negative proof;
- output exposes unknowns/coverage and contains no correct/best/adoption verdict;
- recommended reading uses authorized existing handles and deterministic lineage-diverse ordering.

### Exact proof

- denominator comes only from authoritative inventory plus explicit authorized unsaved snapshot set;
- plan binds exact source/workspace/inventory/owner/access/purge/shadow/observation/overlay/profile fences;
- every denominator item appears exactly once as completed result or explicit failure;
- reads reopen exact planned retained/stable revisions, never whatever currently occupies a path;
- Qdrant/top-k/lexical/semantic candidates never define or narrow the denominator;
- raw-byte, decoded-text and structural-IR predicate domains remain distinct;
- regex engine/profile is pinned, non-backtracking and explicitly bounded;
- timeout/cancellation/read failure/revision loss/scope drift/gap/access/purge/unsaved expiry blocks a
  complete negative claim;
- `NoMatchInCompleteScope` requires zero matches, zero failures/omissions and all completeness flags;
- proof concerns only the compiled predicate and exact frozen scope, never arbitrary semantic absence;
- restrictive security changes block unauthorized match/report/handle emission immediately;
- historical frozen proof and current-workspace proof are classified separately under later drift.

## Stop conditions

Any of the following keeps W6 unavailable:

- resolver silently picks one materially ambiguous candidate;
- explicit stale/revoked handle falls through to unrelated lower-tier candidate;
- candidates from different source/workspace/security fences are mixed;
- fork/mirror copies inflate independent evidence count;
- tests/docs treated as automatic truth;
- mutually exclusive cfg variants labeled conflict or unknown cfg treated universal;
- output contains correctness/best/adoption decision;
- exact denominator derived from Qdrant, top-k, ranked candidates or caller-authored file list;
- regex/provider identity incomplete or backtracking/resource bounds unproved;
- incomplete item accounting or unreadable/drift/cancel/timeout/gap produces complete negative;
- current file substituted for unavailable planned revision;
- exact match cites Qdrant payload rather than exact source readback;
- semantic absence claimed from an exact lexical/name predicate;
- missing raw evidence, mandatory `UNAVAILABLE` probe or self-review.

## Evidence products

Each probe record binds exact command/fixture, commit/API/profile/configuration/source-view identities,
platform/resource envelope, start/end time, `PASS | FAIL | UNAVAILABLE`, raw output digest and
independent reviewer. Prose-only evidence is rejected.
