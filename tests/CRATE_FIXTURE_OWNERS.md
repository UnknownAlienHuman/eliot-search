# Fixture ownership during cutover

The former package/receipt ownership matrix is superseded. It assigned work to deleted or removal-target
packages and required typed requests/merge receipts. Do not recreate that approval system or preserve a fixture
because a historical row names its owner.

The manager changes each affected implementation and its real consumers together. A useful fixture follows the
operation it exercises, not the old crate name. Delete fixtures that only freeze removed topology, receipts,
lexical vector goldens, point reclamation, grants or lifecycle state machines.

Use the [current owner map](../docs/implementation/README.md#owners) and [test cutover](../docs/implementation/TEST_CUTOVER.md).
No search-eval package, port conformance platform, point reclaimer or separate handle store is a prerequisite.
Optional feature cases apply only when their real producer/consumer is selected.

The [prior matrix](https://github.com/UnknownAlienHuman/eliot-search/blob/44ee1661833c1139f1e0f1486f365a3a523fe814/tests/CRATE_FIXTURE_OWNERS.md)
is available only to interpret old fixtures. This file neither requires a new test suite now nor establishes
that any existing fixture was run.
